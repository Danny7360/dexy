# Appendix D: FAQ and Objections

## 1. “Isn’t this too easy now that everyone can AI-code?”

If the product is just a dashboard or an explanation wrapper, yes.

Dexy only works if it becomes:

- persistent
- wallet-specific
- action-prioritized
- embedded in workflow

The moat cannot be “we can analyze public data.”

## 2. “Why wouldn’t users just use CoinMarketMan or HyperTracker?”

They will, unless Dexy provides one of these advantages:

- continuous alerts
- wallet-specific monitoring
- better attribution
- better prioritization
- a more action-oriented workflow

If Dexy only rephrases what existing dashboards already show, it should not be built.

## 3. “Why wouldn’t Hyperliquid build this?”

Hyperliquid may build more native analytics over time.

Dexy only keeps room if it stays:

- more operator-specific
- more workflow-driven
- more attribution-focused
- more wallet-aware

## 4. “Isn’t public alpha a better business?”

Not for this founder path.

Public alpha businesses suffer from:

- decay
- leakage
- distrust
- copy risk

Dexy is explicitly avoiding this trap.

## 5. “Is this a sexy venture-scale story?”

Not at first.

Phase 1 is likely a narrower professional workflow business.

It becomes more venture-like only if it grows from:

- dashboard

into:

- workflow
- API
- flow-linked economics

## 6. “Why should anyone pay?”

Only if Dexy helps them:

- avoid a meaningful mistake
- catch risk earlier
- understand a recurring loss pattern
- save time on repeated wallet review

If it does not change behavior, it is not worth paying for.

## 7. “What should kill the project?”

The project should be reconsidered if:

- users say free tools are enough
- no one returns repeatedly
- no one pays for risk/attribution
- the founder keeps drifting back to signal-selling

## 8. “What is the right first mental model?”

Not:

- AI analyst
- signal seller
- trading copilot

But:

- wallet risk layer
- attribution engine
- operator control surface
